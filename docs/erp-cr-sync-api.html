Integration guide · for the ERP team

PM Tools ERP CR Sync API

ERP CR Management pushes its Change Requests into DWS PM Tools. ERP sends its own values: ERP statuses, segment and stage, High/Medium/Low, emails and codes. PM translates them, so ERP never needs PM's internal IDs or vocabulary.

Each environment has its own API client and secret. Never use a production secret on staging.

How it works

One keyEach CR is identified by its ERP Ticket Number, e.g. #ERPO138381.
Send the whole CROn every change in ERP, PUT the full current CR. PM creates it the first time and updates it after.
Newest winsEach message carries occurredAt. PM ignores anything older than what it already applied.
Nightly catch-upA batch of all open CRs at 02:00 WIB corrects anything missed during the day.

02Authentication

The PM admin creates an API client for ERP with the scope cr:sync and sends you a clientId and clientSecret, one pair per environment.

Request
POST /api/auth/client-token
Content-Type: application/json

{ "clientId": "erp-cr-prod", "clientSecret": "<secret>" }
Response 200
{ "access_token": "eyJhbGciOi…", "token_type": "Bearer", "expires_in": 1800, "scope": "cr:sync" }
  • Send Authorization: Bearer <access_token> on every call.
  • The token lasts 30 minutes and there is no refresh token. Get a new one shortly before it expires, or when a call returns 401.
  • A cr:sync client can call only the endpoints in this guide. Any other PM endpoint returns 403.

03Create or update a CR

PUT/api/v1/integrations/erp/crs/{ticketNumber}
  • {ticketNumber} is the ERP Ticket Number, URL-encoded: # becomes %23, so #ERPO138381 → /crs/%23ERPO138381. Matching ignores upper/lower case and a leading #.
  • Call it on every change: created, signature added, stage changed, status changed, dates changed, closed or cancelled.
  • The body always holds the full current CR.
Request body
{
  "eventId": "6c1b0f0e-6a0e-4c2e-9d0a-5b6c1a2f9e11",
  "eventType": "cr.stage_changed",
  "occurredAt": "2026-11-12T03:15:00Z",
  "cr": {
    "ticketNumber": "#ERPO138381",
    "crId": "CR000000123",
    "url": "https://erp.example/cr/CR000000123",
    "type": "Change Request",
    "projectType": false,
    "changeRequest": "<p>Add vendor tax field to ZMM001 …</p>",
    "note": "Needed before month-end closing",
    "moduleId": "FI",
    "moduleName": "Financial Accounting",
    "tCode": "ZMM001",
    "functionalDepartment": "SAP FICO Team",
    "requesterDepartmentCode": "AP1",
    "ownership": { "code": "OWN-01", "name": "Finance" },
    "impactArea": { "code": "IA-03", "name": "Payables" },
    "priority": "High",
    "requesterEmail": "budi@kpn-corp.com",
    "functionalEmail": "adinda.nisa@kpn-corp.com",
    "deptHeadEmail": "head.finance@kpn-corp.com",
    "deptHeadName": "Head Finance",
    "dateCreation": "2026-11-02",
    "targetResolved": "2026-12-15",
    "createdAt": "2026-11-02T02:10:00Z",
    "closedAt": null,
    "status": "In Progress",
    "segment": "FSD Creation & Approval",
    "stage": "Developer Review",
    "crReference": "#ERPO130001"
  }
}

Envelope fields

FieldRequiredDescription
occurredAtRequiredISO 8601 time of the change in ERP. PM ignores a message whose occurredAt is not newer than the last one applied to that CR.
eventIdRecommendedUnique ID of this message (UUID). If ERP sends the same eventId again (a retry), PM returns its first answer and doesn't apply the message twice.
eventTypeOptionalFree text for the log: cr.created, cr.signed, cr.stage_changed, cr.status_changed, cr.closed, cr.cancelled, cr.reconcile.
crRequiredThe CR (next section).

05Response and warnings

201 Created for a new CR; 200 OK otherwise.

Response
{
  "action": "updated",
  "ticketNumber": "#ERPO138381",
  "initiativeId": "be9f61b0-3a61-4a9e-b8e7-b9e814ad7070",
  "pmTicket": "CR12112026001",
  "pmUrl": "https://pm.energi-up.com/#view/be9f61b0-…",
  "changedFields": ["milestone"],
  "warnings": []
}
actionMeaning
createdNew CR created in PM (201)
updatedSomething changed. changedFields lists PM's field names.
unchangedThe message matched what PM already had
ignored_staleoccurredAt is older than the last change applied. Nothing was done. Not an error; don't retry.
  • pmTicket is PM's own CR number and pmUrl opens the CR in PM. ERP may store both to show a "View in PM" link.
  • A repeated eventId returns the first answer plus "duplicateEvent": true.

Warnings

A warning means PM saved the CR but couldn't map one value, so that PM field was left unchanged. PM keeps the warnings with the CR and in its integration log, and the PM team fixes the mapping. ERP doesn't need to retry: the next message for that CR picks up the fixed mapping.

CodeFieldMeaning
USER_UNMAPPEDrequesterEmail / functionalEmailNo active PM user with this email
USER_CREATEDdeptHeadEmailPM created an inactive user for the Dept Head
UNKNOWN_MODULEmoduleIdPM doesn't know this module and no moduleName was sent
UNMAPPED_MODULEmoduleIdNo PM System Impacted is mapped to this module yet
UNMAPPED_DEPARTMENTrequesterDepartmentCodeNo PM department holds this code
UNMAPPED_STAGEstageThis segment/stage pair isn't in the mapping

06Other endpoints

Partial update (optional)

PATCH/api/v1/integrations/erp/crs/{ticketNumber}
  • Same body as PUT, but every cr field is optional; only the fields sent change. occurredAt is still required.
  • The CR must already exist in PM, otherwise 404. Create CRs with PUT.
  • segment and stage must be sent together.
  • Prefer PUT. A lost PATCH is only corrected by the next full PUT or by the nightly batch.
Request body
{ "eventId": "…", "occurredAt": "2026-11-20T08:00:00Z", "cr": { "segment": "Development and SIT", "stage": "SIT" } }

Batch (max 200)

PUT/api/v1/integrations/erp/crs

For the nightly reconciliation and the first load of existing CRs. Each item is the same object as the PUT body, including cr.ticketNumber.

Request body
{ "items": [ { "eventId": "…", "occurredAt": "…", "cr": { "ticketNumber": "#ERPO1", … } }, … ] }
Response 200
{
  "created": 1, "updated": 3, "failed": 1,
  "results": [
    { "index": 0, "httpStatus": 200, "action": "updated", "ticketNumber": "#ERPO1", … },
    { "index": 1, "httpStatus": 400, "ticketNumber": "#ERPO2", "error": "cr.status must be In Progress, Delayed, Completed or Cancelled" }
  ]
}

The batch call returns 200 even when some items fail. Check each item's httpStatus and error; a failed item doesn't stop the others.

CR document

PUT/api/v1/integrations/erp/crs/{ticketNumber}/document
  • multipart/form-data, one file in the field file, max 30 MB (larger returns 413).
  • The CR must exist; create it with PUT first.
  • ERP keeps one document per CR, so a new upload replaces the one sent before. Documents that PM users upload themselves are not touched.
curl
curl -X PUT "https://pm.energi-up.com/api/v1/integrations/erp/crs/%23ERPO138381/document" \
  -H "Authorization: Bearer $TOKEN" -F "file=@CR-ERPO138381.pdf"
Response 200
{ "action": "added", "ticketNumber": "#ERPO138381", "initiativeId": "…", "documentId": "…", "fileName": "CR-ERPO138381.pdf", "sizeBytes": 523144 }

action is added or replaced.

Module master

PUT/api/v1/integrations/erp/modules

Send ERP's module list once, then again whenever it changes. The PM admin uses it to map each module to a PM System Impacted (SAP FICO / SAP NON FICO).

Request body
{ "items": [ { "id": "FI", "name": "Financial Accounting", "description": null, "departmentId": "…", "isActive": true } ] }
Response 200
{ "created": 1, "updated": 0, "unchanged": 0 }
  • id is ERP modules.id and must never change.
  • A module that is no longer used should be sent with isActive: false. Modules missing from the list are not deleted.

07Errors, retries, ordering

HTTPMeaningWhat ERP should do
200 / 201Done (read any warnings)—
400Invalid message; error names the fieldFix the data. Don't resend unchanged.
401Token missing or expiredGet a new token and retry
403Wrong scope or endpointConfiguration problem: contact the PM admin
404CR not in PM (PATCH, GET, document)Send the full CR with PUT first
409This Ticket Number is linked to a PM Project, not a CRContact the PM admin
413Document larger than 30 MB—
5xxPM unavailable or slowRetry (below)

Error body: { "error": "text" }.

  • Retry on 401 (after a new token) and on 5xx or timeouts: wait 1 min, 5 min, 30 min, then 2 h; after that, alert. Re-send the same eventId.
  • Order: messages may arrive late or out of order. PM compares occurredAt and keeps only the newest state, so ERP doesn't need a strict queue. Fill occurredAt from the time of the change, not the time of sending.
  • Timeout: 30 seconds per call.
  • Nightly reconciliation (02:00 WIB): through the batch endpoint, send every CR that isn't Completed or Cancelled, plus those closed in the last 30 days. Use "eventType": "cr.reconcile" and the CR's latest change time as occurredAt.

People

09Go-live checklist

ERP team

  • Store the PM client credentials per environment.
  • PUT the CR on every change, with eventId and occurredAt.
  • Upload the CR document after creating the CR, and when it changes.
  • Send the module master, and again when modules change.
  • Retry on 401 and 5xx; log warnings.
  • Run the nightly reconciliation batch.
  • Optional: show a "View in PM" link from pmUrl.

PM team

  • Create the cr:sync API client for staging and production.
  • Map ERP modules to System Impacted (Master DWS Application).
  • Enter requester-department codes (Departments → ERP codes).
  • Check that IT PIC and requester emails exist in PM.

10Try it on staging

bash
# 1. Get a token
TOKEN=$(curl -s -X POST http://test-pm.kpndomain.com/api/auth/client-token \
  -H "Content-Type: application/json" \
  -d '{"clientId":"<id>","clientSecret":"<secret>"}' | jq -r .access_token)

# 2. Create a test CR
curl -X PUT "http://test-pm.kpndomain.com/api/v1/integrations/erp/crs/%23ERPOTEST1" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"eventId":"test-1","occurredAt":"2026-11-12T03:00:00Z","cr":{"ticketNumber":"#ERPOTEST1","changeRequest":"Test CR","status":"In Progress","segment":"Preparation","stage":"CR Creation","requesterEmail":"<pm user email>","functionalEmail":"<pm user email>","dateCreation":"2026-11-12","targetResolved":"2026-12-12","createdAt":"2026-11-12T03:00:00Z"}}'

# 3. Read it back
curl "http://test-pm.kpndomain.com/api/v1/integrations/erp/crs/%23ERPOTEST1" -H "Authorization: Bearer $TOKEN"
